## Layering (enforced, verified by grep)

```
config
   ↑
hardware   navigation   perception     (no cross-imports between these three)
   ↑___________↑___________↑
               |
            control
               |
        communication   (parallel to control -- talks to it only via callbacks
                          injected by application/main.py, never imports it directly)
               |
          application    (composition root -- the only file importing everything)
```

**Confirmed absent:**
- No file in `hardware/`, `navigation/`, or `perception/` imports `control/`, `communication/`, or `application/`.
- `control/robot_controller.py` does not import `communication/socket_client.py` or `robotx.application.main` — it is decoupled from the transport via `set_telemetry_hook()` and `handle_command()`, both plain callables wired up by `application/main.py`.
- `communication/socket_client.py` does not import `control/` or `hardware/` — it only knows about dict payloads and a generic `CommandHandler` callable type.
- `perception/vision_controller.py` and `perception/decision_engine.py` do not import `hardware/motors.py`, `control/`, or `communication/` — they cannot command a motor even indirectly; they are pure vision-decision code, currently reachable only from `tests/perception/test_vision.py`.
